# User Knows What To Do Checklist

Use this checklist before demos and before future UX changes. A page is not ready if the user must read deeply before understanding their next move.

## Page Clarity

- [ ] Is the primary user obvious?
- [ ] Is the page purpose obvious in one sentence?
- [ ] Is the D5O stage or workflow obvious?
- [ ] Is the current gate/status obvious?
- [ ] Is the blocker obvious?
- [ ] Is the owner obvious?
- [ ] Is the due date obvious?
- [ ] Is the next action obvious?
- [ ] Is the required decision obvious?
- [ ] Is the evidence required obvious?
- [ ] Is the next movement obvious?
- [ ] Is detail hidden until needed?
- [ ] Is the primary CTA clear?

## Role Fit

- [ ] Executive pages emphasize decisions, cash, blocked work, and consequence.
- [ ] PM pages emphasize assigned action, gate blocker, due date, and evidence.
- [ ] Field pages emphasize today’s work, report submission, quantities, and field issues.
- [ ] Finance pages emphasize billing blockers, backup, retainage, and cash risk.
- [ ] Safety pages emphasize overdue corrective actions and safety blockers.
- [ ] Quality pages emphasize missing tests, open deficiencies, punch, and verification.
- [ ] Admin pages emphasize readiness, boundaries, and safe operation.

## Language Standard

- [ ] Use action verbs: approve, hold, submit, resolve, review, escalate, move forward.
- [ ] Avoid generic labels when a role-specific label is clearer.
- [ ] Replace long explanations with concise action language.
- [ ] Keep evidence lists short and scannable.
- [ ] Keep consequence visible but not verbose.

## Guided Workflow Standard

- [ ] The header says who should use the workflow.
- [ ] The role cue says what the workflow produces.
- [ ] Required fields are visually clear.
- [ ] Helper text is short.
- [ ] Final outcome shows decision, evidence, and next gate/status movement.
- [ ] Demo/local-state limitations are visible where relevant.
