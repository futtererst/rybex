# CEO Demo Path

## Opening Line

“RybexOS is the operating system for running subcontracted infrastructure work
with discipline from pursuit through closeout. It does not just track projects;
it encodes how the work should be run.”

## 10-Minute Path

1. Command Center - show the executive cockpit.
2. Pipeline - show go/no-go discipline.
3. Projects - show contract baseline before mobilization.
4. Mobilization - show field-start readiness.
5. Field Execution - show daily proof and issue escalation.
6. Changes and Billing - show margin and cash recovery control.
7. Safety and Quality - show operating evidence and corrective action control.
8. Closeout - show acceptance, final billing, and retainage readiness.
9. Optimize - show production rates, partner performance, and lessons learned.
10. Admin - show enterprise readiness.

Presenter note: the latest visual review approves this path with caveats. Stay
on top summaries, blockers, decision queues, and one proof panel per module;
do not scroll every dense register unless the audience asks for depth.

Role note: for a CEO audience, keep the path centered on Command Center,
Billing, Field Execution, Closeout, and Optimize. Pipeline, Projects, and
Mobilization are proof points for discipline, not places to inspect every row.

## Seven Proof Points

- D5O phase control.
- Go/no-go discipline.
- Contract baseline before mobilization.
- Field readiness gate.
- Daily field control.
- Change, billing, and cash-risk visibility.
- Closeout and optimization loop.

## Workflow Line To Use Throughout

“Every module follows the same operating pattern: a signal triggers a decision, the decision creates an action, the action requires evidence, and that evidence moves a gate or status forward.”

Use this line on Command Center, then repeat it briefly on Pipeline, Mobilization, Field Execution, Billing, Closeout, and Optimize.

## Common Objections

- “Is this just a dashboard?” No. The pages are backed by typed workflow records, gate logic, scoring logic, control logic, and reusable operating components.
- “Is it production-ready?” Not yet. It is seed-data backed, with persistence, RBAC, audit, and route architecture prepared for the next platform pass.
- “Can field crews use it?” The daily report, safety, quality, and mobilization workflows are structured for field-device use, but browser/device QA should be completed before rollout.
- “How does it improve margin?” It protects pursuit quality, scope baseline, change notice, billing backup, approved changes, closeout evidence, and lessons learned.
- “Is it polished enough to show?” Yes, approved with caveats after local screenshot review. The caveat is density below the fold, so demo the operating story rather than every record.
- “Who is this for?” The first demo is for executives and operations leaders. PM, field, finance, safety, quality, estimator, and admin journeys are documented in `docs/role-journey-map.md`.

## Closing Line

“This is the difference between managing projects with spreadsheets and running
work through a controlled operating model.”
