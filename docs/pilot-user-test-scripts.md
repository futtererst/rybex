# Pilot User Test Scripts

Use these scripts during the controlled internal pilot. Each script should be observed by the pilot owner or support owner.

## Executive

Scenario:
Review leadership risk and decide what needs attention.

Starting page:
`/command-center`

Tasks:

- Identify top leadership priorities.
- Identify cash at risk.
- Identify blocked work.
- Open one target module from a workflow card.
- Explain the consequence if the top issue is missed.

Expected outcome:
The executive can name the top decision, owner, due date, risk, and next route.

What to observe:
Does the executive understand the operating story without scrolling into dense detail?

Pass/fail criteria:
Pass if the user can explain what must happen next in under 60 seconds.

## Operations Leader

Scenario:
Assess whether the operating system shows what is blocked across D5O.

Starting page:
`/command-center`

Tasks:

- Review stage/gate health.
- Review escalation queue.
- Drill into Mobilization or Field Execution.
- Identify one action to assign or resolve.

Expected outcome:
The operations leader can prioritize blocked field work and gate movement.

What to observe:
Does the page clarify where operations should intervene?

Pass/fail criteria:
Pass if the user can identify one owner and one required action.

Notes:

## Project Manager

Scenario:
Move a project blocker toward resolution.

Starting page:
`/projects`

Tasks:

- Find the D2 gate or contract-baseline blocker.
- Identify required evidence.
- Complete or simulate a workflow action if available.
- Navigate to Changes or Billing if commercial impact exists.

Expected outcome:
The PM understands what gate movement is blocked and what evidence/action clears it.

What to observe:
Does the PM know whether to approve, hold, escalate, or gather evidence?

Pass/fail criteria:
Pass if the PM can explain blocker, action, evidence, and next movement.

Notes:

## Field Supervisor

Scenario:
Capture field activity and escalate an issue.

Starting page:
`/field-execution`

Tasks:

- Identify today's field signal.
- Open daily report workflow.
- Review evidence requirements.
- Create RFI/change signal or submit daily report action where available.

Expected outcome:
The supervisor understands what proof is needed and where a field issue goes next.

What to observe:
Does the workflow feel field-usable, or too office-heavy?

Pass/fail criteria:
Pass if the supervisor can identify report, issue, evidence, and escalation path.

Notes:

## Billing / Commercial User

Scenario:
Protect cash recovery.

Starting page:
`/billing`

Tasks:

- Identify cash at risk.
- Identify missing backup.
- Identify approved-not-billed change exposure.
- Navigate to supporting change or pay application action.

Expected outcome:
The billing user can name what blocks billing and what backup is required.

What to observe:
Does the page clearly separate billable work, blocked cash, and retainage risk?

Pass/fail criteria:
Pass if the user can identify next billing action and evidence.

Notes:

## Safety / Quality User

Scenario:
Verify field safety/quality closure.

Starting page:
`/safety` or `/quality`

Tasks:

- Identify overdue corrective action or open deficiency.
- Review owner and due date.
- Identify evidence required for closure.
- Navigate to Closeout if the issue blocks acceptance.

Expected outcome:
The user can identify the issue, owner, due date, required evidence, and verification action.

What to observe:
Does the workflow make safety/quality control actionable rather than just informational?

Pass/fail criteria:
Pass if the user can name verification proof and next route.

Notes:

## Admin

Scenario:
Confirm platform readiness and pilot boundaries.

Starting page:
`/admin`

Tasks:

- Confirm current data mode.
- Confirm RBAC/security status.
- Confirm RLS/storage limitations.
- Confirm pilot readiness rating.
- Identify top blockers.
- Explain why the app is not production-ready.

Expected outcome:
Admin can state what is safe to demo or pilot and what remains blocked.

What to observe:
Does Admin read like a credible readiness dashboard rather than a developer dump?

Pass/fail criteria:
Pass if Admin can explain demo ready, controlled pilot candidate, and not production-ready.
